## S-ORG-001 — ภาพโจทย์ Hack Challenge และ Track 3

- ประเภทแหล่งข้อมูล: ภาพจากเอกสารผู้จัดที่ผู้ใช้แนบในบทสนทนา
- วันที่ได้รับ/ตรวจอ่าน: 3 กันยายน 2026
- วันที่เผยแพร่ต้นฉบับ: ไม่ปรากฏในภาพ
- URL ต้นฉบับ: ยังไม่มี
- สถานะ: ใช้ยืนยันเนื้อหาที่มองเห็นในภาพได้ แต่ยังไม่ได้ตรวจ authenticity/เวอร์ชันล่าสุดกับหน้าโครงการหรือแบบฟอร์มทางการ

### ข้อเท็จจริงที่ภาพรองรับโดยตรง

1. ผู้สมัครทุกคนได้รับ Hack Challenge หลักเดียวกัน
2. ในวันแข่งขัน ผู้สมัครถูกแบ่งเป็น 3 Tracks ตามสายงาน/ตำแหน่งที่สมัคร และต้องนำเสนอ Solution ผ่าน technical perspective และทักษะเฉพาะของ Track
3. โจทย์ให้คิด Feature, Function หรือ Solution ใหม่สำหรับ K PLUS เพื่อช่วย First Jobbers:
   - บริหารจัดการเงินและเก็บออมได้ดีขึ้น
   - ลดความเสี่ยงและป้องกันการตกเป็นเหยื่อ Scam หรือ Fraud
4. Solution ต้องเชื่อมโยงกับ Track และตำแหน่งที่ผู้สมัครเลือก
5. Track 3 มีชื่อ `Cyber Security & Digital Trust` และตำแหน่งคือ `Cyber Security`
6. Track 3 เชื่อมกับ Scam และ Fraud โดยตรง และต้องแสดงว่า K PLUS สามารถมี Feature หรือ Solution ที่ช่วย:
   - ป้องกันความเสี่ยง
   - ตรวจจับพฤติกรรมหรือธุรกรรมที่น่าสงสัย
   - แจ้งเตือนผู้ใช้ก่อนเกิดความเสียหาย
   - ลดโอกาสที่ First Jobbers จะตกเป็นเหยื่อ Scam หรือ Fraud
   - สร้างความมั่นใจในการใช้งาน Digital Banking
7. ทีมงานจะพิจารณาความเข้าใจในปัญหา ความเหมาะสมของ Solution และการประยุกต์ใช้ทักษะของแต่ละ Track

### สิ่งที่ภาพชุดนี้ยังไม่ยืนยัน

- ช่วงอายุ 22–30 ปีของ First Jobbers
- จำนวนสมาชิกสูงสุดของทีม
- กำหนดส่ง 21 กันยายน 2026
- Resume/CV และ one-page pitch proposal เป็นเอกสารที่ต้องส่ง
- หัวข้อบังคับทั้ง 5 ส่วนของ Proposal
- ภาษา รูปแบบไฟล์ ขนาดไฟล์ เกณฑ์คะแนนโดยละเอียด และข้อกำหนด prototype
- รายละเอียดความสามารถปัจจุบันของ K PLUS, K-ePocket, MAKE by KBank หรือมาตรการ anti-fraud ของ KBank

### ผลต่อทิศทางแนวคิด

- แกน Track 3 ต้องเป็น security outcome ก่อนเกิดความเสียหาย ไม่ใช่ budgeting เพียงอย่างเดียว
- Detection อย่างเดียวไม่พอ: user journey ต้องเชื่อมจาก risk prevention → suspicious behavior/transaction detection → pre-loss warning/intervention → digital trust
- First Jobber และการจัดการเงิน/เงินออมยังเป็นเงื่อนไขหลัก จึงห้ามเสนอ fraud engine ที่ไม่เชื่อมกับบริบทชีวิตการเงินของกลุ่มเป้าหมาย
- ความเหมาะสมและการประยุกต์ใช้ทักษะ Cyber Security เป็นสิ่งที่ผู้จัดระบุว่าจะพิจารณา จึงควรอธิบาย threat model, signals, risk-based controls, failure modes และ privacy อย่างกระชับและตรวจสอบได้

## S-TH-002 — ธปท.: รวมพลังทุกภาคส่วนเพื่อรับมือภัยการเงินดิจิทัล

- URL: https://www.bot.or.th/th/research-and-publications/articles-and-publications/bot-magazine-issues/phrasiam-69-1/synergy-against-fraud.html
- วันที่เข้าถึง: 3 กันยายน 2026
- ประเภทแหล่งข้อมูล: บทความ ธปท. ที่อ้างข้อมูล Thai Police Online และงานวิจัย/รายงานที่เกี่ยวข้อง
- สิ่งที่รองรับ: ในไตรมาสสุดท้ายปี 2568 การหลอกให้โอนเพื่อทำงานหารายได้พิเศษคิดเป็น 17% ของมูลค่าความเสียหายที่บทความจำแนก หรือกว่า 920 ล้านบาท; รูปแบบหนึ่งคือปลอมเป็นบริษัทรับสมัครงานและให้โอนค่าเริ่มงาน นอกจากนี้บทความอธิบายว่ากลุ่มอายุ 18–40 มีแนวโน้มตกเป็นเหยื่อ และ social engineering ใช้สภาวะอารมณ์เพื่อเร่งการตัดสินใจ
- ข้อจำกัด: หมวด “งานหารายได้พิเศษ/task scam” ไม่เท่ากับ fake recruitment email หลังส่ง Resume และช่วงอายุ 18–40 กว้างกว่า First Jobbers 22–30
